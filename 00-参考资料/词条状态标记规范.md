# 词条状态标记规范

本文档定义词条中的状态标记系统，用于标注**待补充内容**、**存疑信息**、**需要核实**等情况。

---

## 📌 为什么需要状态标记

1. **区分完成度**：明确哪些词条已完成，哪些仍在构建中
2. **记录疑问**：标记设定中的不确定部分，避免忘记
3. **协作友好**：多人协作时，清楚知道哪里需要补充
4. **质量保障**：定期检查带标记的部分，逐步完善

---

## 🏷️ 标记类型

### 1. ✏️ 待补充 (TODO)

**用途**：标记**已知缺失**但计划补充的内容

**语法**：
```markdown
> [!todo] 待补充
> 此处缺少Y35-Y60期间的详细经历
```

**示例场景**：
- 人物生平有明确的时间空白
- 组织历史有未记载的阶段
- 事件缺少某一方的视角

**位置**：
- 放在缺失内容**应该出现的位置**
- 或者放在章节末尾

---

### 2. ❓ 存疑 (QUESTION)

**用途**：标记**不确定**或**可能有冲突**的信息

**语法**：
```markdown
> [!question] 存疑
> 森蒂诺殉道的具体年份，[[时间线]]记载为Y62，但[[司目]]词条记载为Y58-62围城期间
```

**示例场景**：
- 不同来源的信息有矛盾
- 逻辑推理存在疑点
- 时间/地点/人物关系不确定

**位置**：
- 紧跟在存疑信息之后

---

### 3. ⚠️ 需要核实 (WARNING)

**用途**：标记**可能有错误**需要检查的内容

**语法**：
```markdown
> [!warning] 需要核实
> 本词条记载的年份与[[时间线]]不一致，需要对照检查
```

**示例场景**：
- 发现与其他词条的明显矛盾
- 数据计算可能有误
- 引用链接可能错误

**位置**：
- 问题内容附近
- 或词条开头（如果整个词条都需要核实）

---

### 4. 💡 待扩展 (TIP)

**用途**：标记**可以进一步发展**的方向

**语法**：
```markdown
> [!tip] 待扩展
> 可以补充克鲁奇与其他百炼成员的具体互动细节
```

**示例场景**：
- 已有框架，可以深化细节
- 存在创作空间
- 可以补充支线故事

**位置**：
- 章节末尾
- 或单独的"未来扩展"章节

---

### 5. ⛔ 设定冲突 (DANGER)

**用途**：标记**与硬设定矛盾**的严重问题

**语法**：
```markdown
> [!danger] 设定冲突
> 本处描述与[[设定边界]]中的"三枚密钥不可复制"硬设定冲突
```

**示例场景**：
- 违反物理参数（如Aeros尺寸）
- 违反时间线锚点
- 违反核心逻辑

**位置**：
- 冲突内容之前（醒目提示）

---

## 📝 在 Frontmatter 中标记状态

除了正文中的标记，词条的整体状态应在 frontmatter 中声明：

```yaml
---
类型: 人物
状态: 待补充  # 或：完成、存疑、草稿
---
```

### 状态值定义

| 状态值 | 含义 | 说明 |
|--------|------|------|
| **完成** | 词条已完整，无明显缺失 | 默认状态，可随时修改 |
| **待补充** | 有明确缺失部分 | 正文中应有对应的 `[!todo]` 标记 |
| **存疑** | 存在不确定或矛盾的信息 | 正文中应有对应的 `[!question]` 标记 |
| **草稿** | 初稿，结构不完整 | 需要大幅修改 |

## 🔍 标记的查找与清理

### 查找所有待办标记

在 Obsidian 中搜索：
```
[!todo]
```

### 使用 Dataview 自动汇总

如果启用了 Dataview 插件，可以创建自动汇总页面：

```dataview
TABLE 状态, file.ctime as "创建时间"
FROM ""
WHERE 状态 = "待补充" OR 状态 = "存疑"
SORT file.mtime DESC
```

## ✅ 标记使用规范

### 何时添加标记

✅ **应该添加**：
- 写词条时发现信息缺失
- 发现与其他词条可能矛盾
- 想到未来可扩展的方向
- 需要后续核实某个信息

❌ **不应该添加**：
- 故意保持模糊的设定（参考[[设定边界]]的"禁区"）
- 个人主观喜好（"我觉得这个人物应该..."）
- 过度细节（"缺少某某的早餐内容"）

### 何时移除标记

✅ **应该移除**：
- 待补充内容已补充完成
- 存疑信息已核实确认
- 冲突已解决

❌ **不应该移除**：
- 问题未解决就移除标记
- 为了"好看"而隐藏问题

---

## 📊 标记优先级

当一个词条有多个标记时，优先处理顺序：

1. **🔴 设定冲突** - 最高优先级，立即修正
2. **⚠️ 需要核实** - 高优先级，可能影响其他词条
3. **❓ 存疑** - 中优先级，需要调查
4. **✏️ 待补充** - 中优先级，逐步完善
5. **💡 待扩展** - 低优先级，有时间再做

## 🎯 实践示例

### 示例 1：人物词条中的待补充

```markdown
## 生平

### 早年
[[克鲁奇]]约Y-15年前后加入[[百炼]]...

### Y0-Y3: 百炼内部分裂

> [!todo] 待补充
> 此处缺少克鲁奇与塞里斯在Y0-Y2期间的具体争论细节

### Y3-Y5: 崩落派领袖
...
```

### 示例 2：事件词条中的存疑

```markdown
## 事件经过

### Y5秋：崩落指令下达

据[[时间线]]记载，崩落指令在Y5年秋季下达。

> [!question] 存疑
> [[克鲁奇]]词条提到"Y5十月处决"，但未明确是秋季的哪个月。
> 需要确认"Y5秋"与"Y5十月"的时间关系。
```

### 示例 3：概念词条中的待扩展

```markdown
## 相关技术

断域技术包含三个主要分支：网络隔离、骨架替代、无人机行为学。

> [!tip] 待扩展
> 可以为每个分支创建独立的详细词条，补充技术原理和应用案例。
```

## 📋 清理计划

建议定期（如每月）进行标记清理：

1. **统计当前标记数量**
2. **优先处理设定冲突和需核实**
3. **逐步补充待补充内容**
4. **记录存疑问题的调查进展**
